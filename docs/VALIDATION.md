# 验证说明

仓库 CI 执行 Maven verify 和四个应用的集成验证。自动化测试的通过只证明列出的场景，不代表生产高可用、全 MCP 协议或真实企业登录已经验收。

| 层次 | 验证内容 |
|---|---|
| 身份 | 本地 JWKS + 真实 RSA JWT；错误签名、来源、受众和过期 token 被拒绝 |
| 授权 | 无授权默认拒绝；用户 / 角色、组织、来源、组范围、当前修订和资源范围 |
| 目录 | 新工具待发布、变更修订、完整删除、重新出现、过期发现报告、存储恢复 |
| 内部请求 | HMAC 篡改、内容 / 路径绑定、过期、重复请求拒绝 |
| 配置快照 | 刷新失败不清空；不能延长租约或回退版本；过期拒绝 |
| MCP 视图 | 当前测试夹具的列表与初始化摘要不含隐藏工具；错误组、修订不一致不调用上游。未覆盖任意上游 description 的跨工具引用 |
| Agent 客户端 | 官方 MCP Java 客户端连接预先指定的 `/mcp/orders`，完成初始化、用户工具列表和调用；未验证单入口跨组发现 |
| 四进程 | 注册、分页发现、发布、分组、授权、差异列表、调用、撤权、增删改、上游业务错误、重启和租约过期 |
| 管理入口 | 管理员 / 只读 / 发现凭据不能互换；Runtime 不接受匿名直连 |

## 目标架构验收（待实现，未计入现有通过范围）

以下对应 [接入场景与能力视图](ACCESS-MODEL.md) 和 TODO F08、F10、F12、F14、F15、F18、F23、F28。文档修订不构成运行验证。

| 场景 | 验收要求 |
|---|---|
| 固定应用 Key | 有效 Key 返回绑定能力；换 Key 保持主体及适用授权；过期／撤销 Key 拒绝；新工具和新修订不自动继承旧授权 |
| C 端基础工具集 | 同类用户获得相同定义与公共说明；只能访问本人数据；订单状态不符合时业务拒绝，不要求删除整项工具 |
| 员工角色策略 | 按岗位与组范围获得差异工具；角色变更遵循声明的服务端传播及客户端刷新契约 |
| 统一入口 | 只配置 `/mcp` 和认证方式即可获得入口范围内跨组工具，不预先传 groupId；空权限返回空列表 |
| 跨组路由 | 重名工具无冲突；同一工具跨组复用保持组作用域；旧名称不调用其他工具；统一与分组入口权限一致 |
| 文档可见性 | 批准公开的手册可共用；未授权保密章节不泄露；旧管理备注不自动公开；工具引用与对外名称一致 |
| 说明交付 | 组说明／已审核上游说明实际进入选定客户端上下文；不同客户端的支持边界明确 |
| 客户端更新 | 使用真实持久客户端验证工具通知及重新拉取；不支持时验证重连／主动刷新；Doc 及初始化说明单独验证更新 |
| 业务执行上下文 | 平台级调用不强求自然人；用户相关调用采用服务端可信主体与数据范围，伪造 userId 无效，列表查询不串数据 |
| 缓存隔离 | 不同组织、来源、主体、入口和适用版本不串用目录或说明；用户数据不因目录相同而共用 |

当前 smoke 脚本通过重复请求 tools/list 等待服务端变化；这不等同于已经验证通知链路或客户端自动更新。

## 本地复现现有实现

~~~bash
mvn -B -ntp verify
python3 scripts/smoke.py
~~~

应用日志写在被 Git 忽略的 run/test-logs，测试结束前替换本次生成的秘密值。CI 保留 surefire 报告和这些日志。演示数据只在临时目录中存活；不提交企业凭据。

管理页面已经随 Admin 提供，可在本地 demo 手工查看和操作。当前没有浏览器自动化验证记录；图集为可直接渲染的 SVG，不声称经过所有客户端的协议兼容认证。
